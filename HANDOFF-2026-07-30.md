## Root Cause: Bill Breakdown Hallucination

**Symptom:** Apple On-Device provider showed completely fabricated items on the Eureka restaurant receipt — "Korean Beef Skewers," "Asamul, Brisk Tea, Burrito," "2 Brown Rice & a Bag of Kentucky." None of these are from Eureka. The model also reported no subtotal or total found.

**Root cause:** The small on-device Apple Foundation Model was being asked to enumerate every line item from a flattened OCR text of a complex restaurant receipt. This is beyond its capability ceiling:

| Constraint | Value |
|---|---|
| Context window | 4,096 tokens |
| Model type | General-purpose small LLM, no receipt-specific training |
| Task complexity | Enumerate every item with name + exact price from noisy 2-column OCR text |

The model confabulated items from training data when it couldn't reliably parse the receipt structure.

**Why regular receipt logging works fine:** It extracts ONE labeled value — the grand total. `BillTotalsParser` does this deterministically with regex before the model runs. The model only receives a clean scalar extraction task, not a full enumeration.

**What we tried and ruled out:**
- Better prompting — does not fix a model that lacks the reasoning capacity for this task
- `OCRTool` — documented but not present in Xcode 27 beta 4 SDK
- iOS 27 image path — even with `Attachment(image)`, the small model still hallucinated because it's too small for complex structured extraction

## Current Architecture: Bill Breakdown (Apple Provider)

```
itemizeBill(data: Data)
    │
    ├─ VisionLayoutService.recognizeRows(in: data)   [iOS 26+, Vision framework]
    │   └─ RecognizeDocumentsRequest
    │       ├─ document.tables → [LayoutRow(leftText: name, rightText: price)]
    │       └─ document.paragraphs → [LayoutRow by text alignment]
    │
    ├─ VisionLayoutService.layoutString(from: rows)  [deterministic formatting]
    │
    ├─ BillTotalsParser.extractTotals(from: layoutText)  [regex, deterministic]
    │
    └─ itemizeBillDeterministically(rows, layoutText, totals)
        ├─ Items: filter rows where BOTH leftText AND rightText are populated
        │         AND leftText doesn't start with total/tax/header keywords
        │         AND rightText parses as a Double
        │         → zero hallucination, items come from Vision OCR only
        │
        └─ Vendor: small on-device model gets only the top 6 lines of the receipt
                   (single scalar, simple task it handles correctly)
```

**What's intentionally disabled:** Private Cloud Compute (PCC) tier is coded but removed from the call path. See next section.

## The Crash (Fixed)

**Symptom:** App crashed immediately on Bill Breakdown capture after the PCC tier was added.

**Root cause:** `PrivateCloudComputeLanguageModel()` does not throw a catchable Swift error when the `com.apple.developer.private-cloud-compute` entitlement is absent — it terminates the process outright (fatal entitlement violation, similar to accessing the camera without the NSCameraUsageDescription plist key but more severe). `try?` cannot catch a process termination.

**Fix:** Removed the PCC call from `itemizeBill()` until the entitlement is provisioned. The code is preserved in git history at `f2c88af` for easy re-enabling.

```swift
@available(iOS 27.0, *)
private static func itemizeBillViaPCC(
    layoutText: String,
    totals: BillTotalsParser.Totals
) async throws -> ExtractedBill {
    let pccModel = PrivateCloudComputeLanguageModel()
    guard pccModel.isAvailable else {
        throw FoundationModelsError.modelUnavailable("Private Cloud Compute unavailable")
    }
    let instructions = """
    You extract purchased line items from layout-structured OCR text of a \
    restaurant or store bill. Each line is formatted "ItemName    Price" \
    where the right column is the price. Return only individual food, drink, \
    and product lines — NOT subtotal, tax, service charge, tip, or total \
    rows. Never invent items.
    """
    let prompt = """
    Here is layout-structured text from a receipt photo. Each line shows \
    "ItemName    Price". Extract only the individual purchased line items \
    (food, drinks, products) in order. For each: the item name, the quantity \
    (use 1 if not shown), and the price (plain number, no currency symbol). \
    Skip any subtotal, tax, gratuity, or total rows.

    ---
    \(layoutText)
    ---
    """
    let session = LanguageModelSession(model: pccModel, instructions: instructions)
    let response = try await session.respond(to: prompt, generating: BillItemsDraft.self)
    let draft = response.content
    let rawItems = draft.items.map { (name: $0.name, quantity: $0.quantity, price: $0.price) }
    return ExtractedBill.build(
        vendor: draft.vendor.trimmingCharacters(in: .whitespacesAndNewlines),
        rawItems: rawItems,
        subtotal: totals.subtotal, tax: totals.tax,
        serviceCharge: totals.serviceCharge, total: totals.total,
        unreadableLineCount: draft.unreadableLineCount)
}
```

| Issue | Notes |
|---|---|
| `VisionLayoutService` paragraph pairing | Currently leading/trailing paragraphs are separate `LayoutRow` entries with one side empty. If `RecognizeDocumentsRequest` detects items as paragraphs rather than table cells (thermal receipt printers often output monospace text, not formal tables), the deterministic path may return zero items. |

## Key API Notes for Neeraj's Agents

- `RecognizeDocumentsRequest` is **iOS 26.0+** (not iOS 18). The `@available` annotation must match.
- `observations.first?.document` gives `DocumentObservation.Container` (not `observations.first` directly — a common mistake; the property is `.document`).
- `table.rows` returns `[[DocumentObservation.Container.Table.Cell]]` — a 2D array, already row-ordered. Do not manually group by `rowRange`.
- `cell.content` is `DocumentObservation.Container` (non-optional). `.text` is `DocumentObservation.Container.Text` (non-optional). `.transcript` is on `Text`, not on `Container` directly.
- `PrivateCloudComputeLanguageModel()` crashes without the entitlement — it does NOT throw. Do not wrap in `try?`.
- `OCRTool` is in Vision but absent from beta 4 SDK. Do not use until confirmed present.
- `LanguageModelSession(model: PrivateCloudComputeLanguageModel(), instructions: ...)` — the `init(model:tools:instructions:)` form supports all three parameters.
- PCC is **iOS 27.0+**. On-device `SystemLanguageModel` is **iOS 26.0+**.
